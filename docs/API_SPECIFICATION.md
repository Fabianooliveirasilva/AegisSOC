## 1. Conventions

### 1.1 Authentication

| Principal | Mechanism | Endpoints |
|---|---|---|
| User (browser) | Cookie `__Host-aegis_session` (HttpOnly, Secure, SameSite=Strict) + header `X-CSRF-Token` on POST/PUT/PATCH/DELETE | everything except `/ingest/*` |
| Ingestion source | `Authorization: Bearer aik_<key_id>_<secret>` | `/ingest/*` only |
| Anonymous | — | `POST /auth/login`, `GET /health/live`, `GET /health/ready` |

Session cookies are never accepted on `/ingest/*`; API keys are never accepted elsewhere.

### 1.2 Authorisation

Every endpoint declares one permission (table §3). Missing session → `401`; insufficient permission → `403`; resources the caller cannot see → `404` (not `403`) where existence would leak information (e.g. AI analyses of other users).

### 1.3 Errors — RFC 9457 problem details

```json
{
  "type": "https://aegissoc.local/problems/validation-error",
  "title": "Request validation failed",
  "status": 422,
  "detail": "2 fields are invalid",
  "instance": "/api/v1/incidents",
  "request_id": "01JD…",
  "errors": [{"loc": ["body", "severity"], "msg": "Input should be 'low', 'medium', 'high' or 'critical'", "type": "enum"}]
}
```

| Status | `type` slug | When |
|---|---|---|
| 400 | `bad-request` | malformed JSON, invalid cursor |
| 401 | `unauthenticated` | no/invalid session or key |
| 403 | `forbidden` / `csrf-failed` | permission or CSRF failure |
| 404 | `not-found` | |
| 409 | `conflict` / `invalid-transition` / `version-mismatch` | state machine or optimistic-lock violation |
| 413 | `payload-too-large` | body over limit |
| 415 | `unsupported-media-type` | |
| 422 | `validation-error` | schema validation |
| 429 | `rate-limited` / `backpressure` / `ai-budget-exhausted` | includes `Retry-After` |
| 503 | `unavailable` / `ai-disabled` | dependency down, AI off |
| 500 | `internal-error` | never includes stack traces |

### 1.4 Pagination, filtering, sorting

Cursor pagination on all list endpoints: `?limit=50&cursor=<opaque>`; response `{"items": [...], "next_cursor": "…" | null}`. `limit` max 200. Sorting via `sort=-created_at` from an allowlist per resource. Simple filters as query params (`status=new&severity=high,critical`); complex event search uses the DSL body (`POST /events/search`).

### 1.5 Concurrency

Mutable aggregates (alerts, incidents, rules) return `ETag: "<version>"`; updates require `If-Match`; mismatch → `409 version-mismatch`.

### 1.6 Rate limiting

| Scope | Limit |
|---|---|
| `POST /auth/login` | 20/min per IP; per-username progressive delay after 5 consecutive failures (30 s doubling, cap 15 min — D-09) |
| Authenticated user, read | 600/min |
| Authenticated user, write | 120/min |
| `POST /events/search`, hunt runs | 30/min per user |
| `POST /ai/analyses` | 20/hour per user + global daily token budget |
| `/ingest/*` | per source `rate_limit_rps` (default 50 req/s) |

Headers: `RateLimit-Limit`, `RateLimit-Remaining`, `RateLimit-Reset`; on 429 also `Retry-After`.

### 1.7 Versioning

URI major version (`/api/v1`). Additive changes (new optional fields/endpoints) are non-breaking. Breaking changes require `/api/v2` or a deprecation window: `Deprecation` and `Sunset` headers for ≥ one minor release. The CI OpenAPI diff fails on breaking changes unless the PR carries the `api-breaking` label and an ADR reference.

### 1.8 Common headers

Request: `X-Request-ID` optional (generated if absent, echoed in response). Response: `X-Request-ID`, security headers from edge (SR-20).

### 2.2 Authentication and users

| Method | Path | Permission | Notes |
|---|---|---|---|
| POST | `/auth/login` | anonymous | body `{username, password}` → `200 {user, csrf_token}` + Set-Cookie; failure `401` generic |
| POST | `/auth/logout` | authenticated | revokes session, clears cookie, `204` |
| GET | `/auth/me` | authenticated | `{user, permissions[], csrf_token, session: {expires_at, idle_expires_at}}` |
| POST | `/auth/password` | authenticated | `{current_password, new_password}`; revokes other sessions |
| GET | `/users` | `users:manage` | list |
| POST | `/users` | `users:manage` | `{username, display_name, email?, role, password}` |
| GET | `/users/{id}` | `users:manage` | |
| PATCH | `/users/{id}` | `users:manage` | `{display_name?, role?, is_active?}`; admin cannot demote/disable self; changes revoke target's sessions |
| POST | `/users/{id}/reset-login-throttle` | `users:manage` | clears the progressive login delay for that username (D-09); audited |
| GET | `/audit-log` | `audit:read` | filters `actor_id, action, target_type, target_id, from, to` |

`User` schema: `{id, username, display_name, email, role, is_active, last_login_at, created_at}` (never `password_hash`); admins additionally see `login_throttle: {consecutive_failures, retry_after_seconds}` and `last_failed_login_at`.

### 2.4 Events

| Method | Path | Permission | Notes |
|---|---|---|---|
